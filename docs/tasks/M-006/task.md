## 工作与验收

1. 临时裸机使用独立实例/DB/日志数据/缓存，不连接生产数据库、不挂生产目录。使用mock或限额渠道，不作为生产容量证明。
2. 记录DNS→CDN/WAF→Nginx→实例→数据；若client域名指同生产实例，仍共享额度/负载。SSE缓冲/超时/缓存/断线实测。
3. 首启登录、原数据范围、目标provider/CLI/SSE、退出重登、断网/限流/更新验签通过；不扩管理员/云同步。
4. 先核验生产数据库引擎，维护窗口停止写入后保留一致备份、旧镜像digest/配置；临时环境恢复可启动。SQLite/MySQL/PostgreSQL按实际引擎制定命令，不猜默认数据库。
5. 记录恢复点、最大可接受丢失时间窗、公告、失败判定/恢复顺序。新schema不保证旧镜像可用，必要时同时恢复数据库和旧镜像。
6. 人工复核后少量预发，正式tag才更新stable指针。文档已写不等于已上线。

验收：脱敏证据可复现，含版本/SHA、备份恢复结果、风险/首批范围。用户明确知情接受恢复点后数据损失；没有备份/未明确丢失界限不发版。低配环境不承接生产流量。
